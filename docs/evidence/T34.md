## Findings (not fixed here; each is a proposed task in the plan's section 9)

- **T34-a** First pull always names the branch `feature/gh<n>-issue`. `speckit.ghp.pull` runs `ghp branch <n> --apply` (step 3a) before
  `ghp dod` seeds the ledger (step 4), and `branch.title_from_ledger` reads the title only from the ledger, so the slug falls back to `issue`.
  With the ledger present, `ghp branch 196` plans `feature/gh196-t34-live-story-greet-command-fictional`.
- **T34-b** `ghp push` fails on a Project whose built-in `Auto-add sub-issues to project` workflow is on (Project 3 has it on; `ghp doctor`
  warns about it). The issue was created with its parent at 15:23:03/04, `github-project-automation` added it at 15:23:05, and ghp's
  `addProjectV2ItemById` at 15:23:05 got `Content already exists in this project`; the push stopped (exit 1). The second attempt (run C, 6 creates)
  did not hit it, so it is a race. Proposed: treat that error as "already on the board" (re-read the item, carry on), test first.
- **T34-c** Inside the workflow a partly applied push cannot be finished: the error says `re-run ghp push, which resumes`, but a resume re-runs the
  apply against the old plan, which refuses, and the run needs a new run (with its agent steps). The README covers a refused plan, not this case.
- **T34-d** (docs) The questions comment is never edited (`questions.py`: a changed set is a NEW comment; the live run added two). The workflow
  comment above `plan-questions-loop`, the three question gate messages (`or updating the existing questions comment`) and the README row
  (`the same comment is edited`) say otherwise.
- **T34-e** (docs) `sync-loop` cannot sync ticked tasks: `push.py` says a checked box changes nothing (only `ghp done` closes). Live: all 7
  tasks ticked, sync plan `unchanged 7`, sub-issues 0 of 7 closed. The `approve-sync` message and the README (`sync the sub-issue states ticked
  during implement`) say otherwise.
- **T34-f** (wording) `ghp status` prints the first unmet stage as `Issue #196: merged.`, which reads as "is merged" while PR #204 is open.
- **T34-g** (environment) The spawned `claude` loads the operator's global agent config and plugins. Here a rule in that config about
  signing in to `gh` made the agent try `gh auth token` (denied by the deny list) and then run `ghp gate --offline`, so the
  ledger's gate record says drift was `not checked` (the workflow's own `gate-check` step ran online). A live run should use a clean agent home.
- **T34-h** (docs, follow-up) `workflows/ghp-lifecycle/README.md` "Not verified yet: A real run end to end against GitHub" is now answered for
  terminal mode with the `claude` integration; comment mode and the poller (`ghp approvals sync --resume`) are still not run live. The README line,
  its pin in `tests/test_workflow.py` and the plan's section 8 verified list can follow in their own task.
