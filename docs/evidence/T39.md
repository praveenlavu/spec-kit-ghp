## Findings

- **F1 (toolkit, low).** The gate job's failure names no rule in the log or the annotation: only `ghp gate exit 1 ... see the job summary`.
  The job summary is the only place with `ac_traceability`, and it is not returned by the REST API (`output.summary` is `null`) nor shown to a
  signed-out reader, so automation and anonymous readers cannot see why the gate failed. `strict check` and `strict verify` do print rule ids
  (`rule ids: evidence-missing test-command`). Expected (by analogy): the blocking ids in the error line. Actual: run 43325372554, job 131556381439.
- **F2 (doc mismatch, medium).** `docs/ci-github.md`: "When the target branch is in strict mode, it also runs `ghp strict check`." Actual: the
  "Run the strict check" step has no `always()` and is skipped whenever "Run the gate" fails, so on a strict target a gate-blocked PR never shows
  its strict-check findings (the job still fails closed). Run 43325939270, job 131558274116: step 8 "Run the gate: failure", step 9 "Run the strict
  check: skipped". Either the doc should say "if the gate passes", or the step should run regardless.
- **F3 (toolkit maintenance, low).** Every job annotates: `Node.js 20 is deprecated. The following actions target Node.js 20 but are being forced
  to run on Node.js 24: actions/checkout@11bd719..., actions/setup-python@a26af69...`. The pinned actions still work today.
- **F4 (GitHub / my setup, note).** On the brand-new repository the first three `pull_request` events (opening PRs #5 to #7) produced no run at
  all (`actions/runs` `total_count: 0` for several minutes). Runs started only after a first push-triggered diagnostic workflow ran (branch
  `diag/actions`, `.github/workflows/diag.yml`, run https://github.com/praveenlavu/ghp-consumer-scratch/actions/runs/43325327848); the PRs were
  then re-triggered with a body edit (`edited`). Cause not verified. Worth one line in the docs ("if the first PR shows no checks, re-trigger it").
- **F5 (fixture, low, cause unverified).** `ghp pr create`'s preview for case d says `**Ledger summary** (dod/DoD_4.md): 0 acceptance criteria`
  although the fixture ledger lists `AC-1`; the fixture ledger's headings (`## 1. AC`, `## 3. AC`) may not be the form the summary counts.
- Matches the docs: the caller file from `docs/ci-github.md` works unmodified apart from the SHA; an absent secret behind the `secrets:` mapping is
  read as "not set"; the target branch's config wins over the PR's; the issue reads work with the Actions token and no Project.
