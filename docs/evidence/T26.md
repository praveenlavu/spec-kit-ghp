## Probe answers (the T26 UNVERIFIED list)

### (a) Closing keywords: which forms close on a merge into `main`

One fresh issue and one PR per form (run B, issues #52-#67, PRs #68-#83); body or title as shown, merge method as shown. "Scanner" = whether `prs.closing_targets` (the `pr create` refusal scanner) flags the issue in the PR title or body.

| form | merge | closed? | closer | scanner |
|---|---|---|---|---|
| `Closes #N` (AC1, AC3) | merge | yes | PullRequest | flags |
| `closes: #N` | merge | yes (0.6 s) | PullRequest | flags |
| `Fixes:#N` (colon, no space) | merge | NO | - | flags (over-reads) |
| `resolves #N` | merge | yes | PullRequest | flags |
| `Closes https://github.com/<owner>/<repo>/issues/N` | merge | yes | PullRequest | flags |
| `Closes <owner>/<repo>#N` | merge | yes | PullRequest | flags |
| `Closes` then a line break then `#N` | merge | NO | - | flags (over-reads) |
| keyword on the second line of the body | merge | yes | PullRequest | flags |
| inside a code span | merge | NO | - | flags (over-reads) |
| inside a fenced block | merge | NO | - | flags (over-reads) |
| inside an HTML comment | merge | NO | - | flags (over-reads) |
| PR TITLE only, merge commit | merge | yes (3.7 s) | **Commit** = the merge commit (its message holds the PR title); NOT in `closedByPullRequestsReferences` | flags |
| branch commit message only (`Fixes #N`), merge commit | merge | yes | **Commit** = the branch commit | NOT scanned (commit messages: T21a) |
| squash, keyword only in the squash commit message | squash | yes | **Commit** = the squash commit | NOT scanned (T21a) |

Every form the scanner would NOT have caught is a commit message (branch commit, squash commit message); every form that closed through the PR text the scanner catches. The scanner also flags six forms GitHub ignores: that is its stated fail-closed design (over-reading costs a refusal the user can lift), not a defect.

Squash: the PR body counts (closer PullRequest) even when the squash commit text has no keyword; a keyword only in the squash commit message also closes (closer Commit). The PR title counts only when it becomes commit text (merge commit message; squash title when GitHub uses the PR title).

## Findings (new tasks)

- **T26a** `ghp done` cannot close a story whose PR was merged into a non-default branch: GitHub lists no closing reference (`closedByPullRequestsReferences` and the PR's `closingIssuesReferences` are empty); only a `CrossReferencedEvent` (`willCloseTarget: false`, source = the merged PR) remains. Done refuses `E_NOT_MERGED` with no escape. Options: a `--pr N` flag (checked: merged, this repository, body names the issue), or reading cross-references. AC5 waits on it.
- **T26b** A reopened issue's item stays at Done (no automation moves it back); `ghp activate` then refuses it (`E_ALREADY_DONE`) and the board shows an open story as Done. `status`/`doctor` should flag "open issue at Done"; decide whether `activate` may move a reopened issue's item back.
- **T26c** (input to T21a) Commit text closes issues: a branch commit message, a squash commit message, and the PR title through the merge commit message (closer is then a Commit, and the PR is not in `closedByPullRequestsReferences`). `pr create` scans only the PR title and body.
